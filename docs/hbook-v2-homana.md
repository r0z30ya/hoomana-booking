# اتصال هومانا به hbook-v2

هومانا با API داخلی موتور کار می‌کند. برای هر مجموعه یک tenant در موتور ساخته
می‌شود و هر پزشک یک host در همان tenant دارد. کلید موتور رمزگذاری شده و فقط
در سرور هومانا نگهداری می‌شود.

## آماده‌سازی

1. از پایگاه داده نسخه پشتیبان بگیرید. migrationهای هومانا و موتور را پیش از
   استقرار روی یک نسخه آزمایشی اجرا و بررسی کنید.
2. موتور را با PostgreSQL و schema جداگانه مطابق `hbook-v2/docs/DEPLOY.md`
   راه‌اندازی کنید. موتور می‌تواند از همان سرور PostgreSQL هومانا استفاده کند؛
   schema و دسترسی آن باید جدا باشد.
3. migration هومانا را با `prisma migrate deploy` در workspace دیتابیس اجرا کنید.
4. در محیط سرور هومانا `HBOOK_URL` را روی آدرس داخلی موتور شامل `/v1`، و
   `HBOOK_SETUP_TOKEN` را برابر توکن تنظیم‌شده در موتور قرار دهید. تنظیمات
   `HNOBAT_ENCRYPTION_KEY` و `HNOBAT_ENCRYPTION_KEY_VERSION` همچنان برای
   رمزگذاری کلیدها استفاده می‌شوند. کلید رمزگذاری باید پایدار و محرمانه بماند.
5. موتور و API هومانا را مجدداً اجرا کنید. پزشک، ساعت کاری، خدمت، زمان آزاد،
   ثبت و لغو نوبت را از پنل بررسی کنید.

داده‌های موتور قبلی به موتور جدید منتقل نمی‌شوند. پزشکان قدیمی بدون شناسه
موتور جدید با خطای پیکربندی متوقف می‌شوند و نباید با حذف اطلاعات یا ایجاد
خودکار پزشک جدید جایگزین شوند؛ برای آنها مهاجرت و تطبیق جداگانه لازم است.
ثبت اولیه tenant موتور و ذخیره کلید در هومانا تراکنش مشترک ندارند؛ در صورت
قطع ارتباط یا خطای دیتابیس در همین مرحله، پیش از تلاش مجدد tenantهای ایجادشده
در موتور را بررسی کنید.

# وضعیت و نقشه راه هومانا

تاریخ بررسی: ۳ نوامبر ۲۰۲۶. مبنا: بررسی کد، مدل دیتابیس، مسیرهای API، تست‌ها و مستندات موجود. این سند برای پیگیری کارهاست؛ وجود کد به‌تنهایی به معنی تأیید عملکرد در محیط عملیاتی نیست.

وضعیت‌ها: ✅ پیاده‌سازی موجود؛ 🟡 ناقص یا نیازمند اعتبارسنجی؛ ⬜ شروع‌نشده در کد بررسی‌شده. اولویت‌ها: P0 پیش‌نیاز انتشار امن، P1 هسته محصول، P2 توسعه پس از هسته.

## شواهد و محدودیت بررسی

### پیشرفت ۴ نوامبر ۲۰۲۶: هویت و مرز دسترسی

- بررسی نشست در مسیر احراز هویت و تنظیمات کلینیک یکسان شد؛ نشست کاربر غیرفعال یا کلینیک تعلیق‌شده یا مسدود ابطال می‌شود. ورود کاربر غیرفعال با رمز یا OTP نیز رد می‌شود.
- مصرف OTP با شرط اتمیک انجام می‌شود تا دو درخواست هم‌زمان یک کد را دو بار مصرف نکنند؛ کد قدیمی پس از مصرف کد جدید دوباره فعال نمی‌شود و سقف تلاش هنگام مصرف بررسی می‌شود.
- آزمون‌های جدید با دو کلینیک و نقش واقعی برنامه در PostgreSQL محلی، انقضای نشست، وضعیت کلینیک و کاربر، تغییر نقش، عدم مشاهده و تغییر داده کلینیک دیگر، و مصرف هم‌زمان و تکراری OTP را پوشش می‌دهند. داده‌های ساخته‌شده آزمون با شناسه‌های خود آزمون حذف می‌شوند.
- این بررسی جایگزین ممیزی امنیتی کامل، آزمون ارائه‌دهنده واقعی پیامک، بررسی تمام مسیرهای آینده یا آزمون عملیاتی انتهابه‌انتها نیست. محدودسازی تعداد ارسال‌های هم‌زمان OTP نیز به بررسی جداگانه نیاز دارد.

### پیشرفت ۴ نوامبر ۲۰۲۶: ایمن‌سازی اشتراک و دامنه

- API کلینیک فعال‌سازی مستقیم پلن پولی را رد می‌کند؛ تغییر مجاز توسط مدیر پلتفرم از مسیر مدیریتی موجود انجام می‌شود. پرداخت و تأیید تراکنش هنوز پیاده‌سازی نشده است.
- ثبت و بررسی دامنه از پنل کلینیک فقط با اشتراک پولی فعال و معتبر و روشن‌بودن `CUSTOM_DOMAINS_ENABLED` ممکن است. این کلید سراسری پیش‌فرض خاموش است؛ تنظیم مجزای قابلیت برای هر حساب هنوز وجود ندارد. مدیریت دامنه توسط مدیر پلتفرم مستقل از این کلید است.
- بررسی DNS به معنی فعال‌سازی اتصال یا HTTPS نیست. دامنه‌هایی که پیش از اصلاح DNS تأیید شده‌اند نیاز به بررسی جداگانه دارند.
- آزمون‌های مرتبط با دیتابیس محلی PostgreSQL به‌صورت جداگانه موفق شدند: `npx vitest run apps/api/src/tenant/account-routes.test.ts` و `npx vitest run apps/api/src/platform/platform-routes.test.ts`؛ بررسی نوع‌ها و ESLint فایل‌های تغییرکرده نیز موفق بود. یک اجرای هم‌زمان تست‌ها ناپایدار بود و نیاز به بررسی دارد. پرداخت واقعی، DNS واقعی و HTTPS بررسی نشدند.

- مسیرهای مربوط: `apps/api/src/tenant/account-routes.ts`، `apps/api/src/auth/`، `apps/api/src/platform/`، `apps/web/src/panel/PanelShell.tsx` و `packages/db/prisma/schema.prisma`.
- `infra/docs/PROJECT_STATUS.md` گزارش قدیمی‌تری است؛ برخلاف فهرست کارهای باقی‌مانده آن، کد افزودن دامنه و تنظیم SMS اکنون وجود دارد، اما تکمیل عملیاتی آن‌ها نیازمند بررسی است.
- worker فعلی صف آزمایشی `noop` دارد؛ وجود آن به معنی پیاده‌سازی صف یادآوری یا پیامک نیست.
- در محیط بررسی، `node_modules` و فایل `.env` وجود نداشت؛ بنابراین build، تست‌ها و اجرای سرویس‌ها در این بررسی انجام نشدند. تعداد تست‌های موفق گزارش قبلی نتیجه اجرای فعلی نیست.
- دستور `git status` در مسیر فعلی اعلام کرد این پوشه مخزن Git نیست؛ بنابراین وضعیت تغییرات و CI از طریق Git تأیید نشد. پوشه `.github/workflows` نیز در این نسخه مشاهده نشد.
- پس از اتمام هر ردیف، تاریخ، نتیجه تست و موارد باز در همین سند ثبت و وضعیت به‌روز شود.
